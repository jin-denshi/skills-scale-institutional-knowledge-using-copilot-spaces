# OctoAcme Project Management Docs

This folder contains the process documentation for OctoAcme's project management lifecycle. The docs describe a lightweight, end-to-end approach that moves work from idea to delivery and continuous improvement.

## Overall Approach

OctoAcme's project management is guided by five core principles:

- **Customer-first** — prioritize customer value and usability in every decision.
- **Iterative delivery** — deliver small, testable increments and learn from each one.
- **Clear ownership** — each project has a named Project Manager and Product Lead.
- **Data-informed decisions** — measure impact and iterate based on evidence.
- **Psychological safety** — encourage open feedback and learning at every stage.

The lifecycle flows through initiation, planning, execution and tracking, release and deployment, and retrospective, with integrated risk management and communication practices throughout.

## Quick Reference

### Key Roles

| Role | Primary Responsibility |
|---|---|
| Project Manager (PM) | Coordinates delivery, schedules, risk management, and communications |
| Product Manager (PdM) | Defines outcomes, prioritizes backlog, and measures success |
| Developers | Implement features, write tests, participate in design and code reviews |
| QA / Testing | Validate acceptance criteria and product quality |
| Stakeholders | Provide inputs and approvals |

### Key Artifacts

- **Project Charter / One-pager** — captures the initiative goal, scope, and success metrics
- **Roadmap and Release Plan** — maps work to milestones and target dates
- **Sprint / Iteration Backlog** — the ordered list of work committed for the current cycle
- **Acceptance Criteria & Definition of Done** — the quality bar each piece of work must meet
- **Risk Register** — tracks identified risks, likelihood, impact, and mitigations
- **Retrospective Notes and Action Items** — records learnings and committed improvements

### Communication Cadence

| Event | Frequency | Purpose |
|---|---|---|
| Daily Standup | Daily (15 min) | Surface progress, blockers, and dependencies |
| Weekly Delivery Sync | Weekly | Show progress, updates, and flagged risks |
| Sprint / Milestone Review | Per sprint or milestone | Demo work, review metrics, and plan next steps |
| Stakeholder Status Update | As defined in project charter | Keep sponsors and approvers informed |

## How to Use and Maintain These Docs

- **New team members** — start with the [Project Management Overview](octoacme-project-management-overview.md), then read [Roles and Personas](octoacme-roles-and-personas.md) to understand your responsibilities.
- **Starting a project** — follow [Project Initiation](octoacme-project-initiation.md) to validate the idea and complete the charter before moving to planning.
- **During delivery** — use [Execution and Tracking](octoacme-execution-and-tracking.md) and [Risks and Communication](octoacme-risks-and-communication.md) as day-to-day references.
- **Releasing** — check [Release and Deployment](octoacme-release-and-deployment.md) for the readiness checklist before deploying.
- **After release** — run a retrospective using [Retrospective and Continuous Improvement](octoacme-retrospective-and-continuous-improvement.md) and capture action items.

To update these docs, open a pull request with your proposed changes. Keep each document focused on its stage of the lifecycle, and update this README whenever a document is added, removed, or significantly renamed.
